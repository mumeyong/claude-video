# Kenapa AI lupa isi obrolan yang panjang? — format QUICK

> Pilar: B · AI sehari-hari · target 60–75 s (≈ 165–200 kata) · lihat ideas/STRATEGY.md
> Ide: [ideas/31-ai-lupa-obrolan-panjang.md](../../ideas/31-ai-lupa-obrolan-panjang.md)
> Hero object: **papan tulis kelas** — tiap pesan ditulis satu baris; tiap pesan baru, seluruh papan dibaca ulang;
> papan penuh → penghapus nyapu baris paling atas. Satu hal yang cuma Mumeyong bisa bilang: kebiasaan sendiri —
> rangkum dulu, tempel di chat baru (+ sudut infra: papan lebih gede = GPU memory lebih banyak).
> Read-aloud marks: *kata* = tekanan, ' //' = napas.
>
> HOOK — A/B/C (A terpasang):
> A · "Pesan pertama, aku udah bilang namaku. // Satu jam kemudian, dia nanya: *nama kamu siapa?*" (cold open di tengah kejadian)
> B · "Tiap kamu ngetik 'oke', AI baca ulang seluruh obrolan dari awal." (klaim nyeleneh)
> C · "AI-nya nggak pikun. Papannya yang penuh." (mitos dicoret: ~pikun~ → penuh)

## INTRO
[L01] Pesan pertama, aku udah bilang namaku. // Satu jam kemudian, dia nanya: *nama kamu siapa?*
[L02] Dia nggak pikun. // Dia emang *nggak punya* ingatan.

## 00 · BACA ULANG
[L03] AI nggak nyimpen obrolan kamu di kepalanya.
[L04] Tiap kamu kirim pesan, aplikasinya ngirim ulang *seluruh* obrolan, dari baris pertama.
[L05] Kamu ngetik "oke" doang, // dia baca ulang *semuanya*.

## 01 · CONTEXT WINDOW
[L06] Bayangin papan tulis di kelas. // Semua yang dia baca harus *muat* di sini.
[L07] Papan ini namanya *context window*, // ukurannya diitung pakai token, potongan kata.
[L08] Papannya bisa dibikin lebih gede, // tapi tiap baris makan GPU memory. // Makin panjang, makin *mahal*.

## 02 · DIHAPUS
[L09] Obrolan makin panjang, // papannya penuh.
[L10] Biar pesan baru muat, // tulisan paling atas yang *dihapus* duluan.
[L11] Dan namamu, // ada di baris *paling atas*.

## RECAP
[L12] Jadi kalau obrolannya udah panjang, // minta dia *rangkum*, terus buka chat baru.
[L13] Aku sendiri gitu. // Chat baru itu bukan mulai dari nol, // itu *ngapus papan* dengan sengaja.
